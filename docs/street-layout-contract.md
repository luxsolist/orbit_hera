# 공통 가로공간 설계와 검증

## 2026-09-27 종로 도로 폭 오류

보고 좌표: 37.570915, 126.987641 (85_46 청크).

원본의 평행한 두 도로 선분은 각각 28m의 오래된 추정 폭이었다. 공통 `fitStreetWidths`는 주변 건물·담장과의 간섭을 보고 8m와 11.2m로 보정했다. 그러나 청계천 레시피가 보정 전 원본으로 생성되어 `StreetGeometry`에서 이를 다시 28m로 치환했다. 가로수/벤치 배치는 최종 8m·11.2m를 사용했다. 도로 생성과 소품 생성이 서로 다른 지도를 읽은 것이 직접 원인이다. 직전 8m 지형 세분화의 높이 보정 문제는 아니다.

## 최종 도로 형상 계약

- 일반 도로의 최종 중심선·폭이 렌더링의 기준이다. 오래된 주변 문맥/레시피가 그 폭을 복원하거나 확대할 수 없다.
- `scripts/resolved-street-layout.mjs`는 도시 키와 청크 목록을 받아 공통 `MapCorrections`의 시설 분류·폭 보정 결과를 내보낸다. 도시에 고정된 좌표나 별도 폭 계산식이 없다.
- 청계천 빌드도 이 결과를 사용한다. 하천 배치 계산은 원래 중심선과 설계 단면으로 수행한다. 이후에는 하천 주변의 지상 도로도 최종 가로 단면 검사를 통과해야 한다. 실제 교량/고가/지하는 다른 높이의 구조물이므로 지상 폭 제한 대상에서 제외한다. 일반 폭 보정을 하천 배치 이전에 무차별 적용해 하천 길잡이나 설계 단면을 바꾸지 않는다.
- `resolveRoadContext`/`StreetLayout`가 최종 도로를 주변 레시피보다 우선한다. 폭이 바뀌면 연결부 단면도 다시 풀고, 이전 폭으로 구운 차선은 사용하지 않는다. 도로와 소품이 같은 결과를 공유한다.
- 가로수·시설물 위치는 실제 연결된 차도 윤곽을 사용한다. 화단 크기의 여유를 포함해 차도와 겹치는 위치를 제외한다. 교차로 및 굽은 도로의 연결면까지 검사한다. 나뭇잎이 차도 위로 뻗는 것과 줄기·화단이 차도를 차지하는 것은 구분한다.
- 이 경로는 공통 빌드의 청계천 레시피 생성 → 차선 생성 → 높이 보정 → 검증 → 2×2 압축에 연결된다. 신규 맵은 `build-world.mjs`에서 같은 `planStreetSections`를 실행하고 단면 메타데이터를 저장한다. 기존 맵 및 도시별 배치를 적용한 뒤에는 `MapCorrections`에서 같은 함수를 실행한다.

### 검증

`tests/streetLayout.test.ts`는 방향·입력 순서에 관계없이 최종 폭이 우선하며, 연결부 폭도 갱신되는지 검사한다. `tests/seoulStreetLayout.test.ts`는 청계천 4개 타일의 실제 아스팔트/인도 삼각형에서 가로수·시설물 중심과 화단 모서리를 검사한다. 이후 공통 보정이 폭을 다시 바꾸더라도 렌더러가 예전 폭을 복구하지 못하는 경우도 포함한다.

두 테스트는 `validate-city-surfaces.mjs`에 등록했다. 이번 서울 검사에서는 시범구역 4개 타일의 유효 시설물 144개(보고 지점 주변 10개)를 검사해 차도 침범 0건, 인도 외 배치 0건을 확인했다. 청계천 원본·레시피 검사 및 기존 하천·담장·차선 회귀 검사와 함께 빌드/압축을 차단하는 조건으로 실행된다. 결과는 `build/seoul-street-layout-audit.json`, 실행 기록은 `build/seoul-street-contract-build.log`에서 확인한다.

## Bottom-up과 top-down 비교

| 접근 | 장점 | 한계 |
|---|---|---|
| 좌표별 문제에서 출발 | 눈에 보이는 오류를 빠르게 재현하고 검증 가능 | 단계별 중복 처리와 우선순위 충돌을 계속 뒤늦게 발견할 수 있음 |
| 공통 설계 규칙에서 출발 | 도시와 오브젝트가 늘어도 같은 기준을 적용 | 규칙만으로 모든 원본 데이터의 예외를 예측할 수 없고, 일괄 변경 위험이 큼 |

권장: **top-down 설계 + bottom-up 회귀 검증**. 발견한 좌표는 일회성 예외 패치 목록이 아니라 공통 규칙의 검증 사례로 남긴다. 이번 수정은 ‘최종 도로 형상의 단일 기준’이라는 top-down 계약과 해당 좌표의 실제 메시 검증을 함께 추가한 사례다.

## 가로 단면 설계 V1 — 적용 완료

추가 보고 좌표: **37.569006, 126.987573**. 청계천 배치가 새로 만든 짧은 도로 선분에 추정 폭 28m가 남았다. 종전 폭 검사가 배치 이전에만 실행되고 8m 이상의 평행 외벽만 조사해서, 짧은 선분과 건물 모서리를 놓쳤다.

`src/world/streetSection.mjs`가 도시 좌표에 의존하지 않는 단면 설계기다.

1. 건물·작은 시설·담장·수면을 점유 영역으로 등록한다. 차도 선분 전체와 영역 경계 사이의 최소 거리를 계산한다. 평행한 외벽뿐 아니라 짧거나 비스듬한 모서리와 도로 끝부분도 포함한다.
2. 외벽 여유 0.4m와 연결부의 최대 확장량을 먼저 확보한다. 일반 도로의 보도는 한쪽당 목표 2.3m, 축소 시 최소 1.5m를 우선 배정하고 남는 공간으로 차도를 제한한다. 원본 폭은 상한으로만 사용한다.
3. 최소 차도·보도를 함께 확보할 수 없는 좁은 통로는 분리 연석과 식재 없는 공유 골목으로 처리한다. 도로 중심선이 건물/수면을 관통해 안전한 단면이 없는 경우 `conflict`로 기록하고 새 식재를 금지한다. 도로 링크 전체를 삭제하거나 임의로 우회시키지 않고 기존 중심선 연결을 보존한다. `StreetEnvelope`가 건물·담장·수면의 점유 면적을 제외한 공간에서 도로 면을 생성한다. 장애물과 겹친 부분만 잘라내며 보정용 덧댐 면을 추가하지 않는다. 원본 연결망의 모순 자체는 미해결로 보고하고, 자동 우회 경로를 만들었다고 간주하지 않는다.
4. 연결된 도로의 좁아지는 폭을 주변으로 완만하게 전파한다. 좁은 곳을 다시 넓혀 매끈하게 보이게 만드는 것은 금지한다.
5. `streetSection`에 원본 폭, 확정 차도 폭, 보도 폭, 식재 가능 여부, 확보 거리, 명시 폭과의 모순을 보존한다. 도로·차선·연석·소품·이동 지지면이 같은 최종 단면과 연결 형상을 사용한다. 구형 텍스처 도로도 같은 보도 값을 사용한다.
6. 가로수/화단은 0.9m의 크기 여유까지 들어가는 보도에만 배치한다. 다른 차도와 겹치는 교차로/평행 도로 내부 공간은 기존 최종 메시 검사로 제외한다.

고의로 도로 축이나 건물을 옮기지 않는 **보수적인 대칭 단면**이다. 전체 도시의 비대칭 도로 중심선 재설계, 평행 도로들을 하나의 가로로 통합하는 최적화, 잘못된 원본 중심선의 자동 우회까지 완료한 것은 아니다. 원본 충돌 목록은 검토 대상으로 남긴다.

### 빌드와 검증

- `node scripts/build-city-surfaces.mjs <city>`: 도시 배치, 도로 높이/세분화, 공통 단면, 회귀 검사.
- `node scripts/audit-street-sections.mjs <city>`: 등록된 도시의 모든 타일 검사. `build/<city>-street-section-audit.json`에 폭 축소, 공유 골목, 중심선 충돌, 명시 폭 변경을 기록한다. 계약 위반은 빌드/압축을 중단하고 원본 충돌은 숨기지 않고 보고한다.
- `node scripts/build-map-bundles.mjs <city>`: 같은 검증 통과 후 2×2 압축.
- `tests/streetSection.test.ts`: 모서리 침범, 보도 우선 배분, 협소 통로, 교량 분리, 명시 폭 모순, 단면 전이.
- `tests/seoulStreetLayout.test.ts`: 실제 아스팔트/인도 메시와 보고 위치의 건물 내부 표본, 통행 차도 연속성 및 기존 4개 타일의 시설물 배치. 최신 집계는 `build/seoul-street-section-target.json` 및 `build/seoul-street-layout-audit.json`.

## 후속 확장 기준

1. **의미 분류:** 지상 차도/보도/교량/지하 통로/물/건물/소형 시설을 구분하고 신뢰도와 출처를 보존한다.
2. **수평 공간 배분:** 도로 중심선 하나만 넓히지 말고 건물 사이 전체 가로공간을 확보해 차도·보도·식재대 폭을 함께 배분한다. 일반 보도 목표 2.3m 같은 값은 도시별 설정으로 둔다. 공간이 부족하면 추정 차도 폭, 식재 여부, 공유 골목 여부를 함께 결정한다. 명시 폭이나 설계 구조물과 충돌하면 검토 대상으로 남긴다.
3. **수직 연결:** 확정한 수평 영역을 바탕으로 지면·도로·하천 단면과 건물 기초를 연결한다. 교량과 하부 하천은 별도의 지지 높이를 유지한다.
4. **공통 형상 산출:** 차도·인도·연석·차선·소품·충돌을 같은 최종 배치 결과에서 파생한다. 교차로는 도로 면의 합집합에서 내부 연석을 제거하고 보행 가능 영역을 계산한다.
5. **결과물 검증:** 원본 태그의 숫자 일치보다 실제 메시의 차도 침범, 인도 단절, 구조물 접지, 물/도로 교차, 타일 이음매 및 이동 가능성을 우선 검사한다. 보정 제외/실패 이유를 기록한다.
6. **제한 적용 후 확대:** 대표 구간(밀집 도심, 골목, 언덕, 하천, 교량)을 고정해 전후 품질·프레임 비용을 비교하고 도시 전체로 확장한다.

V1은 공통 가로 단면을 구현한다. 다음 확장에서는 원본 중심선 충돌을 자동으로 숨기는 대신, 평행 차도 묶음과 교차로 경계를 함께 설계하고 보행 영역의 연결성을 검증한다. 도시별 예외 좌표를 늘리는 방식으로 해결하지 않는다.
