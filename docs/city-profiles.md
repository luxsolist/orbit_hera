# 도시별 외형 설정

도시 외형의 진입점은 `src/world/cities/index.ts`의 `cityAppearance(mapId)`다.
`StreamingWorld`가 선택된 전장의 ID로 프로필을 선택하고 청크 생성과 하늘/조명에 전달한다.
위경도 셀을 공유하는 도시가 있으므로 좌표가 아니라 전장 ID로 선택한다.
현재는 선택한 전장 전체에 한 프로필을 적용하며 인접 도시 경계에서 자동 혼합하지 않는다.

## 파일 및 역할
- `types.ts`: 건물, 지면, 도로, 가로시설, 환경의 공통 계약.
- `seoul.ts`: 서울의 16색 사진 샘플 보정, 색상 가중치, 지붕색 및 기존 디테일 설정.
- `index.ts`: 전장 ID와 프로필 연결. 미등록 도시는 기존 기본 외형 유지.
- `BuildingFacade`, `StreetSurface`, `UrbanGround`, `StreetProps`: 설정을 받아 그리는 공통 렌더러.
- `CitySurfaceMaps`: 텍스처 디렉터리별 캐시. 서로 다른 도시의 텍스처가 섞이지 않는다.

## 조정 가능한 값
- buildings: 외벽 colors/weights, roofs, 치수 기반 건물 유형 기준,
  texturePath, windowContrast(0=창문 색 대비 없음, 1=현재), windowSpacing(양수 배율),
  architectureStrength(0=입구/상점/분할 디테일 제거, 1=현재).
- ground: 포장 추정 영역 활성화, 건물 주변 포장 폭과 색상, 지도 구역 종류별 색상.
- street: 차도/보도/경계/차선 색상. 보도 폭과 교차로 생성 방식은 아직 공통이다.
- props: 전체 및 나무/가로등 개별 활성화, 청크당 상한, 도로 샘플 간격,
  최소 간격, 차도 가장자리로부터 거리, 나무 크기, 가로등 높이, 금속/줄기/잎 색상.
- environment: 하늘/안개 색과 환경광/태양/보조광 색상 및 세기.

## 새 도시 추가
1. `cities/<city>.ts`에 `CityAppearance` 객체를 만든다. 기존 프로필을 참고하되
   수정할 중첩 객체와 배열은 새로 만든다. 런타임에서 등록 프로필을 변경하지 않는다.
2. `index.ts`에서 import한 뒤 실제 전장 ID를 키로 등록한다.
3. `public/textures/city/<city>/`에 concrete/brick/roof 각각
   color, normal, roughness PNG 9장을 넣고 texturePath를 지정한다.
   파일명 예: `concrete-color.png`. 공유 텍스처를 쓰면 같은 경로를 지정해 중복 로드를 피한다.
4. 팔레트 weights는 colors와 같은 길이, 음수 없는 값, 합계는 양수로 지정한다.
   colors/roofs는 비어 있으면 안 된다. 길이와 크기 값은 m 단위이며 양수로 설정한다.
5. 해당 도시를 다시 로드해 확인한다. 프로필별 머티리얼은 청크 간 공유되고
   청크 해제 때 지오메트리만 해제한다. 텍스처는 경로별로 앱 수명 동안 공유한다.

현재 가로수/가로등의 기본 조형과 건물 외벽 셰이더는 공통이다. 도시별 독자적인
나무 수종 모델, 전통 건축 메시, 가로등 모델 파일은 아직 추가되지 않았다.
형태 자체를 바꿀 때는 해당 공통 렌더러에 모델 선택 항목을 확장한다.
서울 외 도시의 사진 기반 팔레트/특징은 임의로 만들지 않았다.

독립성 검증: `tests/cityAppearance.test.ts`에서 도시별 벽/지붕 색, 건물 유형,
재질 공유 범위, 가로시설 상한/높이/색, 외벽 셰이더 설정 및 기본 폴백을 검증한다.
기존 standalone 비교 페이지의 boolean 상세 옵션은 호환용으로 유지된다(true=서울).

도로 상세 옵션: `street.geometry`로 별도 도로 면을 선택하고,
`curbHeight`(m, 0=입체 경계석 끄기), `junctionMarkings`(교차로 차선 정리/추정 횡단보도),
`wearStrength`(0~1, 보수 흔적의 어두워지는 비율)를 도시별로 설정한다.


## 서울·부산 애니메이션풍 적용

서울/부산 스트리밍 지도 전체에 `cities/painted.ts`의 독립 프로필을 등록했다. 부산은 동일한 미술 기준으로 시작하며 건물·가로수·도로·조명 설정을 별도로 조정할 수 있다. 지도 배치와 충돌은 원본 데이터를 유지한다. `PaintedCityStyle.ts`는 청크 생성 시 재질을 복제하고 해제 시 정리한다. 하늘은 카메라를 따라 이동하며 지도 종료 시 해제한다. 게임 블룸은 밝은 외벽이 번지지 않도록 문턱을 높이고 강한 에너지 효과는 유지한다. 비교 페이지의 고정 1.5배 해상도는 게임에 강제하지 않고 기존 기기별 품질 설정을 따른다.

## 현지 시간에 따른 낮·밤
서울(37.5665, 126.978)과 부산(35.1796, 129.0756)은 Asia/Seoul 현지 시간을 사용한다. CityTime.ts는 UTC 현재 시각과 위도·경도로 NOAA 근사 태양 위치를 계산한다. 기기 시계를 사용하며 날씨 API나 실제 구름 관측은 포함하지 않는다. 광원·안개·하늘·창문·가로등은 연속 전환하고 1초 간격으로 갱신한다. 야간에는 게임 가시성을 위해 주변광과 건물 명암 하한을 유지한다. 창문은 고정된 방별 패턴으로 일부만 점등하며 가로등은 발광 렌즈 방식(개별 실시간 광원은 아님)이다.

비교 페이지는 현지 현재 시간/아침/낮/저녁/밤 및 시간 슬라이더를 제공한다. 아침·저녁 버튼은 오늘의 태양 고도 약 3도에 해당하는 시간으로 고정한다. 고정 모드는 비교 페이지에만 적용하며 게임은 실시간이다. 두 비교 창 모두 같은 시간·태양 위치를 사용한다.

계산 근거: https://gml.noaa.gov/grad/solcalc/solareqns.PDF

## 인트로 서울 거리
인트로 시작 전에 서울 79/47 지도 JSON을 준비하고, 거리 장면은 게임과 같은 paintedSeoul 프로필로 생성한다. SeoulStudyLocation.ts가 비교 페이지와 인트로의 교차로 선택을 공유한다. 첫 장면 카메라는 고정 교차로의 (18,42,24) 오프셋에서 출발한다. 거리 배우 좌표 원점은 해당 교차로 지표면이다. 실시간 SkyEnvironment를 갱신하고 도시 블룸 및 환경광도 게임 기준에 맞춘다. 실내 조종실은 기존 연출을 유지한다. 붕괴 컷은 지도 건물 중 교차로에 가장 가까운 한 건물의 정점 높이를 낮추며 게임 원본 데이터는 변경하지 않는다. 새 컷마다 청크를 다시 생성하고 이전 컷 재질·지오메트리를 해제한다.
