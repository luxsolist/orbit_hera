## 빌드 우선순위 (§9.7 "수요 순")

1. **1장 열지도 25곳** — 캠페인 최초 진입 장이라 최우선.
2. **2장 자매쌍 20곳** — 2장 앵커(자매도시 2연전) 직결.
3. **3장 태평양 연안 20곳** — 3장 삼각측량 + 계시(5장) 후보지.
4. **4~6장 확장 33곳** — 계시 이후 콘텐츠, 급하지 않음(P5 성능 트랙과 함께).

부산 상하이 이중 결연처럼 겹치는 자매 관계는 구현 시 `campaign.pairAggravation`이 다대다 관계를
지원하는지 확인 필요(현재는 `PAIR_DEFS` 선형 탐색이라 다대다 자체는 되지만, 밸런스 검토는 별도).

## 랜드마크 카탈로그 (2026-08-21 큐레이션 완료, 2026-08-22 실측 좌표 채움)

100개 도시 전체에 대해 도시당 10~25개씩, 총 **1,749개** 랜드마크를 큐레이션해
[`scripts/data/landmark-catalog.json`](../../scripts/data/landmark-catalog.json)에 기록했다(5개
조사 에이전트 병렬 분담, 각 20개 도시).

**수집 방침**: 이름·영문명(가능한 경우)·얽힘 택소노미(`cls`, §8 6종)·5~15자 설명을 수집했다.
실존 확인 가능한 곳만 선정했고, 개수보다 정확성을 우선했다(예: 뤄양은 8개로 다른 도시보다 적음 —
무리하게 채우지 않음).

**실측 좌표(2026-08-22 완료)**: Nominatim(OpenStreetMap) 지오코딩으로 **1,574개(90.0%)**에
실제 위경도(`lat`/`lon`) + 매칭 근거(`geocodeSource`: OSM type/id·표시명·중요도·도시중심과의
거리)를 채웠다. **좌표 날조는 하지 않음** — 지오코딩에 실패한 175개(10.0%)는 좌표 없이
`geocodeStatus: "unresolved"`로만 표시했고, 향후 수동 검수 대상으로 남겨뒀다(주로 OSM에 뚜렷한
포인트 태그가 없는 재래시장·소규모 유적·현지어 고유명 등). 오매칭 방지를 위해 도시 중심 기준
거리검증을 적용했다(1차 bbox 경계, 2차 120km 반경, 3차 대도시 100km/일반 60km 반경) — 예를 들어
"Umayyad Mosque"·"Bab Tuma" 같은 동명이지(암만·로테르담 등)는 거리검증으로 정상 배제됐다.
재현 절차와 원본 요청/응답 로그는 `scripts/data/geocode-landmarks.py`(1차) →
`scripts/data/geocode-retry.py`(2차) → `scripts/data/geocode-retry2.py`(3차) 및
`scripts/data/geocode-*-log.jsonl` 참조.

**연결 지점**: 이 데이터는 아직 어떤 빌드 스크립트에서도 읽지 않는 참고자료다.
