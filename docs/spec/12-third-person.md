# 12 · 드론 3인칭 게임 통합

2026-09-12. 기존 전투 수치와 물리 좌표를 유지하며 워커/플라이어 런타임 모델을 실제 게임에 연결한다.

## 좌표와 책임

- `PlayerController.worldPosition`: 물리·적 추적·피해·리스폰 기준. 기존 eyeHeight 의미 유지.
- `PlayerController.camera`: 호환용 내부 카메라. `getAimDirection()`은 흔들림 없는 yaw/pitch에서 산출.
- `DronePresentation.camera`: 실제 화면·HUD 투영·왜곡용 후방 카메라. 기체와 별도 위치.
- 워커 모델 원점은 worldPosition - eyeHeight, 플라이어 모델 원점은 worldPosition.
- 프로시저 모델을 재사용하므로 미리보기와 관절·스킨·불꽃이 동일하다. GLB는 교환용 정적 산출물.

## 화면과 움직임

- 워커 거리 7.5m / 높이 +1.5m, 플라이어 거리 5.2m / 높이 +1.3m. FOV는 기존 80/88도.
- 카메라는 위치에 즉시 추종한다. 장애물에서 즉시 당겨지고 공간이 열리면 부드럽게 복귀한다.
- 카메라 근접면의 대각 모서리를 포함한 9개 차폐 선분 및 지형 샘플로 벽/지면 접근을 검사한다. 근접 시 기체 외피를 흐리게 한다.
- 기체의 뱅킹과 카메라를 분리하여 수평선을 유지한다.
- 워커는 실제 속도 기반 보행, 대시 다리 기울기, 공중 자세, 착지, 추력을 재사용한다. 양발 지면 높이는 ±0.35m 범위에서 보정한다.
- 플라이어는 호버 불꽃과 속도 기반 후방 추력을 사용한다. 옥상 위 최소 고도 보정은 완만하게 올라가도록 한다.
- 락온 자동 추적은 정지 거리 밴드 근처에서 감속한다. 수동 입력은 기존 속도 우선.

## 사격과 전투

- 화면 조준선으로 목표점을 고르고 각 렌즈에서 별도 레이를 검사한다.
- 동체→렌즈 차폐 검사로 벽을 뚫고 내민 무기 사격을 막는다.
- 렌즈→목표 경로가 막히면 빔은 그 장애물에서 끝난다. 가려진 채널은 피해를 주지 않는다.
- 워커 주무기는 양팔 교대 단일 채널, 플라이어는 두 채널. 발사 수 증가로 워커 피해를 두 배로 만들지 않는다.
- 자동사격은 조준축 기준 반각 워커 60도, 플라이어 45도. 자동사거리 1000m, 수동 2000m 및 기존 비용/피해 유지.
- 후방을 포함한 위협 표시와 적의 추적/피해는 기존 물리 위치 기준이다.
- 피격 시 동체에 짧은 붉은 발광. 후방 보조 화면에서는 자기 기체만 제외한다.
- 특수 살포와 연사도 실제 렌즈와 건물 차폐를 사용한다.

## 스킨·조명·입력

- 접속/일시정지 패널에서 기본형·옵시디언·폴라리스·듄 센티널 선택. 기체별 선택 저장.
- 스킨은 재질/장식만 변경한다. 충돌 반경/피해 범위/속도는 동일하다.
- 도시 환경에 반사 환경맵을 제공하며 종료 시 관련 자원을 반납한다.
- 마우스 잠금 실패 시 접속 버튼을 다시 표시한다. 대기 중에도 도시 청크를 로드한다.
- 마우스 잠금을 지원하지 않는 내장 브라우저에서는 `/?controls=touch`로 터치 조작 모드를 선택할 수 있다. 모바일은 기존 자동 감지 유지.

## 검증과 후속 조정 범위

- 회귀 테스트: 기체/카메라 독립, 실제 렌즈 좌표, 벽 카메라 축소, 고속 추종, 한쪽 렌즈 차폐.
- 기존 이동·건물·무기·미션 테스트를 함께 실행한다.
- 실제 도시의 골목/옥상/고속 비행과 모바일 프레임은 별도 플레이 검증 대상이다.
- 워커의 원형 판정은 유지하고 플라이어에는 기수·꼬리 보조 원형 판정을 추가한다. 날개·장식 전체를 정밀 충돌로 바꾸지 않는다.
- 지면 보정은 소규모 단차 대응이며 모든 계단/교량을 정확히 디디는 전신 물리 IK는 아니다.
- 전방 자동사격으로 후방 방어력이 달라진다. 장시간 난이도 평가는 후속 플레이에서 조정한다.

검증 기록: 전체 83개 테스트 파일/1,613개 통과 후 이동 통합 2개를 추가하여 관련 89개 테스트 재통과. 서울 전장에서 워커/플라이어 렌더, 플라이어 자동사격 처치, HUD·도시 스트리밍 확인. 내장 브라우저의 Pointer Lock 미지원은 터치 모드로 검증했으며 실제 모바일 GPU 성능 수치는 측정하지 않았다.

## 도시 이동·조준 보완 (2026-09-12)

- 카메라 근접면의 가로·세로 폭을 반영하고 0.2m 간격으로 지형을 검사한다. 극단적으로 가까워지면 자기 기체를 숨긴다.
- 플라이어의 앞뒤 0.8m 지점에 반경 0.65m 보조 충돌 검사를 적용한다. 기체 피치에 따른 위치·높이도 반영한다.
- 카메라가 선택한 적의 중심으로 각 렌즈를 수렴시켜 근접한 큰 적의 표면 때문에 사격이 막히는 문제를 방지한다. 실제 렌즈 경로의 차폐는 계속 검사한다.
- 건물 뒤의 적은 조준 보정 후보에서 제외한다. 수동 주무기 경로가 막히면 조준선 아래에 ‘무기 앞 장애물’을 잠시 표시한다.
- 워커 착지 압축은 착지 직전 하강 속도에 비례한다. 가벼운 착지에서는 적게, 빠른 낙하에서는 깊게 굽힌다.
- 관련 5개 파일 114개 테스트 통과: 근접/원거리 양쪽 렌즈, 대각 카메라 장애물, 지형 접촉, 카메라 복귀, 고속 플라이어 충돌, 옥상 고도 보정, 기존 이동·빔·보행 회귀 검사.

## 전투 공정성·성능 보완 (2026-09-12)

### 적용

- 건물을 사이에 둔 러셔 접촉 공격을 차단한다. 카이터 드레인과 동일하게 플레이어까지 경로가 열려야 피해·흡수 성장이 발생한다. 플라즈모이드의 건물 통과 이동 자체는 유지한다.
- 사거리·공격 쿨다운·경직·동결·위상·도약 회복을 먼저 검사한다. 공격 불가 상태에서는 건물 차폐를 조회하지 않는다. 벽에 막힌 공격은 쿨다운을 소모하지 않아 경로가 열리면 즉시 재시도한다.
- 주무기와 특수 연사의 조준 보정은 사거리·전방 콘 후보를 먼저 고른 뒤 정렬 순서로 차폐를 검사한다. 첫 가시 목표를 찾으면 중단한다.
- 카메라 충돌 계산의 임시 벡터와 피격 색상 객체를 재사용한다. 지형 검사 간격과 충돌 안전 범위는 유지한다.

### 현재 밸런스 판단

- 워커 전진 13.89m/s, 후진 6.94m/s, 횡이동 4m/s 대비 러셔 기본 속도 범위 12~17m/s이므로 후진만으로 계속 거리를 벌리기 어렵다. 대시 83.33m/s와 점프·엄폐가 회피 수단이다.
- 자동사격 전방 반각은 워커 60도, 플라이어 45도다. 후방 적은 후방 화면·미니맵·피해 방향 표시로 확인하고 선회해 대응한다.
- 워커 자동사격 비용은 초당 20, 기본 회복은 초당 28이다. 수동 동시 발사와 환경 회복 배수에 따라 고갈될 수 있으며 25% 자동사격 바닥 제한은 유지한다.
- 이번에는 무기 피해·체력·적 속도 수치를 바꾸지 않았다. 벽 너머 피해 제거와 조준 신뢰성 확보 후 실제 전투 기록으로 난이도를 조정한다.

### 검증과 한계

- 전체 84개 파일, 1,625개 테스트 통과. 적 2,000마리가 조준 후보 밖에 있고 정면 목표가 보이는 경우 차폐 조회 1회임을 검증했다.
- 벽에 막힌 러셔/카이터가 피해·성장을 일으키지 않는지, 벽이 열리면 즉시 공격하는지, 쿨다운 중 차폐 조회를 생략하는지 검증했다.
- 계산량 감소 검증이며 실기기 FPS 개선 수치는 아니다. 모바일 GPU, 장시간 전투 생존율·처치 시간·주파수 고갈 비율 측정은 후속 검증 대상이다.

## 실측 기록 (2026-09-12)

`?controls=touch&diag`에서 전투 계측을 표시한다. 일반 플레이 화면에는 추가 표시가 없다. 세션마다 초기화되며 플레이 중 전경 프레임만 수집한다. 프레임 시간은 물리 업데이트의 50ms 제한을 적용하기 전 값이다. p95는 1ms 단위 히스토그램이며 2,000ms 이상은 마지막 구간으로 합친다. 메모리는 실행 시간에 따라 늘어나지 않는다.

환경: Codex 내장 데스크톱 브라우저, 서울, 표시 2560×1440 / 내부 캔버스 3840×2160, 터치 UI, 빌드·테스트 병행 없음. 출격 후 이동·수동 사격 없는 자동 방어 관찰. 초기 로드 프레임 포함. 각 출격에서 미션이 무작위 선택되어 동일 난이도의 통제 비교는 아니다.

계측 테스트 3개 통과: 실제/시뮬레이션 시간 분리, 시간 가중 주파수 부족 비율, 첫 파괴 보존, 잘못된 시간 입력 제외 및 세션 초기화. 타입 검사와 배포 빌드 통과(기존 번들 크기·난독화 소스맵 경고 유지).

## 렌더 해상도·후처리 최적화 (2026-09-12)

- 내부 3D 렌더 픽셀 수는 1920×1080 상당을 상한으로 하고 DPR은 최대 1로 제한한다. 화면 비율은 유지한다. 2560×1440 화면에서는 1920×1080으로 렌더링한다. CSS HUD·글자·터치 버튼의 크기/해상도는 바꾸지 않는다.
- 창 크기가 바뀌면 렌더러와 게임·인트로·메뉴 컴포저의 픽셀 비율을 함께 갱신한다.
- UnrealBloomPass 생성자에 전달한 해상도는 EffectComposer.addPass/setSize가 덮어쓰므로, setSize에서 절반 비율을 유지하도록 수정했다. 밝기·임계값·효과 반경은 유지한다.
- 화면에 위상 왜곡 대상이 없으면 LensDistortPass를 비활성화한다. 대상이 다시 나타나는 프레임에 즉시 활성화한다.
- 관련 테스트 10개 통과: 해상도 상한, 반복 리사이즈 후 블룸 타깃 크기, 왜곡 비활성/재활성, 기존 렌즈 좌표 변환.

최적화 후 실측: 같은 내장 브라우저/서울/플라이어 듄 센티널/정지 자동사격 조건, CLEAR 6기 미션. 70.2초 동안 평균 34.8 FPS, p95 40ms, 게임 시간 68.6초. 내부 캔버스 1920×1080 확인. 처치 0, 파괴 0, 주파수 25% 미만 4.2%. 이전 플라이어 기록은 19.0 FPS/p95 65ms였으나 미션·배치가 달라 통제된 A/B 성능 배율은 아니다. 화면에서 드론/HUD/후방 뷰의 표시를 확인했고 브라우저 오류는 없었다. 빌드와 타입 검사 통과. 60 FPS 달성 및 모바일 실기기 검증은 남아 있다.

## 빠른 조작감 우선 튜닝 (2026-09-12)

최고 속도와 대시·점프 수치는 유지하고 속도 응답 계수를 변경했다. 워커 지상 4→18/s, 공중 2→10/s, 플라이어 9→14/s. 기존 지수 보간 방식을 유지하므로 입력 반응은 빨라지고 속도는 연속적으로 연결된다. 물리적 관성보다 빠른 게임 조작을 우선한 값이다.

목표 속도 90% 도달 시간(ln(10)/응답계수, 충돌·프레임 양자화 제외): 워커 지상 0.576→0.128초, 공중 1.151→0.230초, 플라이어 0.256→0.164초. 이 수치는 장치 입력 지연이 아니라 이동 가속 응답 시간이다. 워커 전진 최고속에서 손을 놓았을 때 연속시간 모델의 총 미끄러짐은 약 3.47→0.77m다.

- 테스트 종료 시 코드를 반영한 전장 선택 메뉴로 복귀했다.

### 리스폰 직후 화면 버튼 사격 검증
- 진단 모드(`?diag`)에만 `리스폰 확인 (횟수 소모)` 버튼을 추가했다. HP를 0으로 만들어 기존 사망/리스폰 경로를 실행하며 실제 리스폰 예산을 소모한다.
- 실화면 검증에서 발견: 기존 화면 전투 버튼은 touch 이벤트만 수신하므로 데스크톱 클릭은 수동 사격 증거가 아니었다. 이전 기록의 버튼 클릭 성공을 실제 발사 성공으로 해석하면 안 된다.
- 버튼 입력을 Pointer Events로 통일해 마우스/터치/펜을 지원한다. 캡처 해제/취소 시 홀드 해제, 기본 빔은 firePressed도 기록하고 Game이 이를 소비해 프레임 사이의 짧은 입력 누락을 방지한다.
- 워커 보호막 2.9초, 플라이어 2.8초가 남은 화면에서 클릭 후 보호막 안내와 실드가 사라진 것을 확인했다. 두 사선 모두 건물에 막혀 `무기 앞 장애물`을 표시했다. 개방 사선의 빔/무기 정렬 및 자동사격 재개는 기존 기하/발사 조건 테스트로 검증했으며 이번 실화면에서 재확인한 것으로 주장하지 않는다.
- 관련 25개 테스트 및 신규 포인터 입력 테스트 1개 통과. 브라우저 오류 없음. 마지막 화면은 플라이어 전투 일시정지.
