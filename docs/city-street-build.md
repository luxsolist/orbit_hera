## 공통 확대 경로

config/street-regions.json에서 coverage를 manifest로 지정하면 해당 도시 tiles.json의 전체 범위를 사용한다. 서울의 범위는 64..103 × 26..65, 1,600청크이며 전송 단위는 기존 2×2 묶음 400개다. 종로–청계천 시범구역은 enabled:false, 서울 전체는 enabled:true로 전환했다. 공통 전체 빌드 하나만 적용하여 중복을 방지한다.

도로의 의미·연결과 차도/보도 배치는 도시 전체에서 정한다. 경계 확장/축소 같은 유한 거리 연산만 여유 영역을 포함한 내부 작업 영역으로 나누고, 작업 영역 경계를 잘라 합친다. 이는 각 청크에서 도로를 따로 설계하는 방식이 아니다. 양수/음수 거리 연산 및 경계에 걸친 구멍의 회귀 검사를 포함한다.

원본 XML은 스트리밍으로 읽는다. 중간 면/최종 메시 파일도 청크별로 저장하고 색인과 파일 해시로 연결하여 큰 JSON 하나를 메모리에 올리지 않는다. 건물·장애물 준비, 도로 여유 공간과 경로 계산은 입력 및 관련 함수의 해시를 키로 재사용한다. 캐시는 build/streets 안의 로컬 중간 산출물이며 게임/배포 데이터가 아니다.

## 실행과 활성화

~~~bash
npm run build:street-regions -- seoul city-wide
node scripts/pack-street-region.mjs seoul city-wide
~~~

첫 명령은 준비 → 설계 → 메시 생성 → 면/지지/충돌/청크 경계 검사 → 보정 파일 반영 순서다. 둘째 명령은 검증 결과와 해시를 확인하고 400개 묶음을 생성한 뒤 인덱스를 마지막에 교체한다. 현재 실행 화면의 전환 기준은 이 인덱스다. Git 커밋/푸시와 GitHub Releases 게시를 자동으로 수행하지 않는다.

기존 build:city-surfaces 역시 enabled:true인 가로 빌드를 호출한다. 도로 보정 파일이 없던 빈 청크도 빈 높이 패치와 최종 가로 산출물을 저장하고 공통 보정 인덱스에 등록한다. 완성된 가로가 청크 전체를 담당하면 런타임의 구버전 도로 재생성을 생략한다. 게임과 도시 뷰어의 데이터 및 코드는 동일하다.

공유 경계의 높이는 인접 청크들을 함께 참고한 동일한 32m 간격 프로필을 사용한다. 네 청크가 만나는 모서리도 하나의 값을 사용한다. 실제 렌더링 삼각형과 이동 지지 높이를 같은 데이터에서 읽는다.

## 검증

- 미해결 우회 경로가 있으면 도시 전체 면 생성 전에 보고서를 남기고 실패 처리한다.
- 도시 청크 목록과 산출물 목록을 정확히 대조한다.
- 원본에서 유지하는 지상 경로의 샘플뿐 아니라 선 전체 누락 길이를 검사한다.
- 차도/건물, 차도/보도 면 소유권을 검사한다.
- 완성 메시를 다시 면으로 합쳐 원래 최종 설계 면과 비교한다.
- 시설 받침 전체, 렌더링과 동일한 지지면, 건물 충돌, 인접 청크 이음을 검사한다.
- 각 청크 파일의 해시와 감사가 수행된 색인 해시가 다르면 반영을 중단한다.

검사 실패를 경고로 낮추거나 제보 좌표별 예외로 우회하지 않는다. 전체 적용 결과 및 수치는 완료한 감사 보고서를 기준으로 기록한다.

## 대규모 면 연산

독립적으로 잘린 경계에는 미세한 부동소수점 차이가 있으므로 `coverage_union_all`의 완전 일치 가정을 사용하지 않는다. 분리된 하위 집합을 합치는 공통 병합기를 사용한다. 기본 차도, 고가면, 보도 여유 영역, 초기 차도, 공유 통로 합성, 최종 차도와 보도는 입력/함수 해시별 중간 파일로 저장한다. 캐시 사용 여부와 관계없이 최종 면·충돌·이음 검사는 동일하게 수행한다.

미세한 내부 구멍 보정은 해당 내곽 링만 제거하고 그 안에 포함된 기존 차도 섬의 중복을 제거한다. 보도에서는 새로 메운 작은 영역만 뺀다. 도로 연속성 감사는 준비된 최종 면을 먼저 조회하고 후보 구간에만 동일한 거리 오차(점 0.06m, 선 0.001m)를 적용한다. 표본점 사이의 단절도 선 전체 길이 검사로 검출한다.

차도/보도 중간 캐시의 의존성은 해당 단계까지의 설계 코드와 공통 형상 함수다. 후속 검증/시설 배치만 수정하면 앞선 면 계산을 재사용할 수 있다. 최종 게시 검사는 별도로 전체 빌드 소스 해시를 확인하므로, 코드가 바뀐 최종 산출물을 검증 없이 게시할 수 없다.

지도 외곽은 사각형 전용 절삭 후 유효성을 확인한다. 연석/중앙선의 여유폭 연산 역시 여유 영역을 둔 분할 교차로 계산한다. 선이 타일 경계 위에 있을 때 빠른 사각 절삭에서 소실되지 않도록 미세한 확장 후 정확히 자른다. 분할 결과가 전역 연산과 같은 면적·길이를 갖는 회귀 검사를 유지한다.

상부 도로는 지상 차도와 별도로 분할·저장하며, 건물 외곽 때문에 상부 경로가 사라지는지 별도 감사한다. 같은 재질의 도로라도 층위별 메시를 보존한다. 공중·지상 지지면의 선택과 표시는 동일한 삼각형을 사용한다.

초기 폭 계산에서 5cm 여유를 인정했던 경로도 최종 면에서는 정확한 선 전체 포함을 요구한다. 좁은 통행 구간은 최종 단면 안에서 통행 폭을 재배분하고 보도에서 같은 영역을 뺀 뒤 연석·중앙선·시설 배치를 생성한다. 얇은 표시용 패치를 런타임에 덧붙이지 않는다. 회귀 검사는 2cm 경계 누락도 최종 도로면에 포함되고 차도/보도 점유가 겹치지 않는지 확인한다.

청크 경계 절단에서 극도로 얇은 도형이 3점 링으로 퇴화하면 빠른 사각 절단 대신 정확한 교차 연산으로 다시 계산한다. 도형을 누락시키거나 검사 기준을 완화하지 않는다. 전체 설계 체크포인트 이후의 저장·삼각형 단계만 재실행할 수 있다.

현재 전체 설계 감사: 경로 표본 10,360,593개, 누락 0개, 미포함 경로 길이 0m, 건물 중첩 0㎡, 차도/보도 수치 중첩 0.005254㎡(허용 0.01㎡ 미만), 시설 배치 80,999개. 최종 메시·압축 활성화도 아래 전수 검사를 통과했다.

충돌 삼각형은 변 길이에 비해 면적이 1e-10 이하인 퇴화 삼각형을 제외한다. 콜라이더의 반평면이 도로까지 무한히 확장되는 오류를 방지하며 실제 면적이 있는 건물은 유지한다.

최종 메시를 만들기 전에 청크 경계의 지면/도로 격자 높이를 공동 프로필로 맞춘다. 내부 격자 높이는 유지하고, 경계 격자를 산출물에 함께 저장하여 지형 메시와 이동 판정이 같이 사용한다. 경계 감사는 도로 메시가 없는 쪽도 실제 지면 높이로 비교하며, 도로가 없는 경계까지 포함한다. 지면 위에 추가 평면을 덧붙이는 방식이 아니다.

하천 횡단 보간도 공통 경계 격자에 먼저 반영한다. 경계의 도로 정점에 횡단 보간을 다시 적용하지 않아, 같은 경계에서 보도와 지면이 서로 다른 높이를 사용하는 이중 보정을 방지한다.

로컬 배포 확인: 2×2 압축 400개, 고유 청크 1,600개, 상부 도로 포함 청크 1,004개. 모든 묶음의 SHA-256과 내부 streetPlan 소스 해시를 다시 검증했다. 압축 합계 1,150,389,832바이트, 원문 합계 3,254,656,458바이트다. GitHub Releases의 기존 배포본은 이번 로컬 적용으로 갱신되지 않으며, 게시 절차는 별도로 실행해야 한다.

저장 형식 후속 변경: [완성 지도 청크](completed-map-chunks.md)로 전환했다. 서울의 road-grade/detail/appearance 별도 파일 대신 기존 지도 청크에 최종 결과와 재빌드 입력을 함께 저장한다. 위 설계·검증 규칙은 그대로 유지한다.


다른 도시 확장과 비파괴 시범 검증은 [도시 공통 가로 빌드](common-street-build.md)를 따른다. 도시별 수정 코드를 복제하지 않고 공유 프로필과 입력 역할을 확장한다.
