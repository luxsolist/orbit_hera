# 서울 2×2 지도 묶음

서울 [37,126] 셀 1,600청크를 400묶음으로 전송한다. 각 묶음에는 원본 지형/오브젝트, 서울 상세(랜드마크 외형·배치 포함), 도로 높이 보정, 랜드마크 외벽 보정을 함께 넣는다. 기존 보정 적용 순서와 개별 청크의 메시/충돌 생성 단위는 유지한다. 경복궁 등 코드에 정의된 특수 모델 생성기와 공통 재질은 앱 코드로 계속 공유하며 중복 포장하지 않는다.

- 생성: `npm run build:seoul-bundles`. 원본 지도/서울 상세/외벽/도로 패치를 수정한 후 실행한다. 빌드 산출물은 `public/maps/bundles/seoul`, 인덱스는 `src/world/seoul-bundles.json`이다.
- 형식: gzip 레벨 6으로 압축한 JSON. `.bin` 바이트를 내려받아 DecompressionStream으로 직접 해제하므로 정적 호스팅의 Content-Encoding 설정이 필요 없다. `.bin`에 별도로 gzip Content-Encoding을 지정하지 않는다.
- 파일명에 압축 내용 SHA-256의 앞 16자 포함. 인덱스는 앱과 함께 배포한다. 변경된 묶음만 새 URL을 사용한다. 배포 전 원본/묶음 동등성 테스트가 오래된 묶음을 검출한다.
- 다운로드는 준비 큐에 들어갈 때 시작하며, 같은 URL의 진행 중 요청을 공유한다. 압축 캐시는 16MiB, 해석 캐시는 JSON 크기의 3배를 추정값으로 사용해 32MiB로 제한한다. 실제 JS 힙 상한을 보장하는 수치는 아니다.
- 한 청크 취소 시 공유 다운로드는 유지하고 해당 생성 작업만 취소한다. 워커가 재시작돼도 메인 스레드 압축 캐시가 유지된다. 모델 생성은 준비된 청크 중 우선순위 순서로 한 개씩 진행한다.
- 서울 묶음 오류는 한 번 재시도 후 명시적으로 실패한다. 압축 해제를 지원하지 않는 브라우저의 개별 파일 경로는 로컬 원본이 있을 때만 사용 가능하다. 다른 도시의 전송 방식은 유지한다.
- 편집용 원본은 로컬 및 Releases에서 보존하고 Git 추적에서 제외한다. 원본이 복원된 개발 폴더에는 압축 묶음 약 16.34MB가 추가된다. 깨끗한 체크아웃은 서울 원본 없이 빌드할 수 있다. 정상적인 서울 청크 요청은 묶음만 사용한다.

생성 시점: 비압축 묶음 JSON 55,543,499 bytes → gzip 16,340,074 bytes. 이는 프로토콜 구조를 포함한 실제 생성 파일 합계이며 기존 비교 실험과 JSON 포맷이 달라 소폭 차이가 있다. FPS 개선 수치는 아직 실측하지 않았다.

원본의 GitHub Releases 관리·복원·게시 절차는 [지도 운영 문서](map-releases.md) 참조. 배포 빌드는 원본 재생성 대신 묶음/릴리스 버전 검증을 수행한다.
