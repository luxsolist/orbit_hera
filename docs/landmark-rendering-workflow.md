# 도시 랜드마크 제작·검증 기준

이 문서는 서울·부산·로마에서 확인한 오류를 다음 도시에서 반복하지 않기 위한 작업 기준이다. 지도 실측 윤곽, 기관 공개 치수, 사진 비율, 추정값을 혼합해 사용하되 근거의 종류를 반드시 구분한다. 사진측량/레이저 스캔을 확보하지 않은 모델을 실측 완전 복원이라고 부르지 않는다.

## 1. 대상 식별을 모델 제작보다 먼저 확정

- 도시 카탈로그의 OSM type/id, Wikidata ID, 좌표, 기관 주소를 대조한다. 이름만 같거나 가장 가까운 건물이라는 이유로 연결하지 않는다.
- 사례: 로마 산 피에트로 대성당이 San Pietro in Vincoli에 잘못 연결되어 있었다. 바티칸 Q12512 / way 244159210로 수정했다.
- 건물·기념물·광장·교량·도로·언덕·지하유적·도시 구역을 구분한다. 광장이나 유적 부지를 하나의 높은 건물로 만들지 않는다. 지하 카타콤베는 지상 고층 모델로 대체하지 않는다.
- 미확정 좌표는 unresolved로 남긴다. 도로 전체를 임의의 한 점으로 단정하지 않는다.

## 2. 출처와 치수 장부

각 대상에 ID, 자료 URL, 확보 날짜, 윤곽 출처, 높이 출처, 본체/첨탑/돔 높이 구분, 사진 추정 항목, 구현 상태를 기록한다. 원본 응답은 재배포 조건을 확인해 별도 캐시 또는 작은 출처 스냅샷으로 보존한다. OSM 추출물은 ODbL 및 기여자 표시를 유지한다. 참고 사진을 텍스처로 무단 복사하지 않는다.

- 건물 높이를 주변 최고 건물에서 전파하지 않는다. 서울 롯데월드타워 주변의 비정상 고층 문제를 재발시키지 않는다.
- 총높이를 본체 높이로 사용하지 않는다. 산 피에트로 돔 136m, 산타 마리아 마조레 종탑 75m를 부지 전체에 적용하지 않는다.
- 자료 간 수치가 다르면 기준점(지반/기단/돔 내부/첨탑 끝)부터 비교한다. 사진 추정치를 heightSource=측량값으로 승격하지 않는다.

## 3. 원본과 모델의 결합

- 원본 청크는 수정하지 않고 도시 상세 오버레이를 생성한다. 원본 블록/셀/단위는 manifest에서 읽는다.
- 윤곽의 경계 상자와 양방향 선분 거리를 함께 검사한다. `scripts/landmark_geometry.py`를 재사용한다. 사각 경계가 같아도 실제 윤곽이 다르면 매칭하지 않는다.
- 0개 매칭은 명시적인 새 원본 형상 추가, 2개 이상은 오류로 처리한다. 반경 내 건물을 일괄 제거하지 않는다.
- 중정·연못·아치·경기장의 빈 공간은 별도로 확인한다. 원본 multipolygon의 inner 링을 잃거나 고대 유적을 완전한 현대식 지붕으로 덮지 않는다.
- 도시 특수 모델은 공통 `MapCorrections` 경로에서 적용한다. 게임·뷰어·청크 worker를 따로 구현하지 않는다.

## 4. 지형과 도로

- 부지 반경 전체를 한 높이로 평탄화하지 않는다. 서울의 도로 융기/경계 낙차 문제는 도로 단면과 타일 경계를 함께 검사한다.
- 기단은 접지면 차이를 메우는 구조물로 처리한다. DEM을 수정하는 경우에는 왜 수정하는지, 영향 범위와 인접 타일 공유 격자를 기록한다.
- 교량은 양쪽 끝에서 지상 도로의 위치·높이·폭·색·차선 패턴을 비교한다. 부산에서 상판만 모델링해 진입부가 끊겼던 문제를 재발시키지 않는다.
- 계단은 양 끝 랜딩을 지형과 연결한다. 계단을 건물 충돌 상자로 등록하지 않는다.
- 시각 모델과 충돌 모델이 다르면 제약을 기록한다. 현재 교량·아치의 정밀 통행/충돌은 별도 검증이 필요하다.

## 5. 재질·문화권·성능

- 도시 팔레트와 실제 석재/벽돌/금속을 구분한다. 야간 발광이나 임시 노란 랜드마크 강조가 실사 재질로 남지 않게 확인한다.
- 한국/중국/일본 처마나 로마 석조 아치처럼 문화권의 구조 차이를 별도 모델 규칙으로 관리한다.
- 같은 창문 무늬를 과하게 반복하지 않는다. 도로 대비와 창문 대비는 원거리에서도 확인한다.
- 작은 장식마다 Mesh/재질을 생성하지 않고 합친 지오메트리·공통 재질을 사용한다. 높은 곳에서 보는 도형 수, worker 준비시간, 청크 활성화 지연도 확인한다.

## 6. 검증과 완료 판정

```bash
npm run audit:landmark-details -- rome
npm test -- tests/romeDetails.test.ts tests/seoulDetails.test.ts tests/busanDetails.test.ts tests/mapLocator.test.ts tests/chunkMesh.test.ts
npm run typecheck
```

공통 감사기는 도시 이름을 받아 원본 윤곽 결합, 중복 ID, 높이 범위, 표면 좌표, 지형 인덱스를 검사한다. 로마 테스트는 원본 불변성, 다른 도시 비간섭, 중복 적용 방지, 모델 좌표·높이·정점 수 및 잘못된 대성당 식별 회귀를 검사한다. 이 자동 검사는 사진 일치나 전투 충돌을 보장하지 않는다.

시각 확인은 동일한 좌표·높이·시선·시간대로 정면/측면/상공을 비교하고, 교량은 양끝과 타일 경계를 별도로 본다. 완료 보고에는 실제 확인한 장소와 남은 근사 요소를 적는다. 보지 않은 화면을 검증 완료로 표시하지 않는다.

압축 도시의 상세 데이터를 바꿨다면 `build:map-bundles → 관련 테스트 → maps:publish:city → maps:verify`를 수행한다. 코드만 바뀌면 모델 코드 재배포가 필요하고, 지도 데이터가 바뀌면 인덱스/묶음/릴리스 포인터를 함께 반영한다. 로마도 2×2 묶음과 Releases를 사용한다. 로마 상세 수정 후에는 `npm run maps:publish:city -- rome`로 갱신한다.
