# 로마·아테네 보행경로 실패 원인 분석

## 범위와 지표의 의미
전체 도시 설계 보고서와 resolved-input, 같은 빌드에 사용한 로컬 OSM XML 태그를 대조했다. 화면 또는 현장 확인 결과가 아니다. 168/77은 보행 네트워크 그래프의 단절 지점 수가 아니라, 생성된 차도·보도 평면이 검사 대상 경로를 덮지 못한 경로 레코드 수다. 계단·승강장·상층 경로의 바닥을 검사하지 않으므로 실제 통행 불가능과 잘못된 검사 층위가 혼재한다.

분류는 각 실패 레코드에 저장된 최대 6개의 대표 샘플 기준이다. 전체 실패 구간의 원인을 각각 확정한 수치가 아니다.

|대표 샘플과 겹치는 원본 영역|로마|아테네|
|---|---:|---:|
|건물|119|11|
|구조물|27|22|
|건물+구조물|1|0|
|수역|21|44|
|합계|168|77|

아테네의 기존 미분류 5개는 선형 수로 중심선 bbox만 검사하던 진단 누락이었다. audit-street-walking.py에 수로 반폭을 더해 재실행하면 전부 수역으로 분류된다. 빌드 형상·검증 허용치는 변경하지 않았다.

## 확인된 공통 원인

### 1. 승강장을 통행 바닥 대신 채워진 장애물로 취급
로마 28개(건물+구조물 1개 포함), 아테네 22개 경로가 원본 platform과 겹친다. osm.mjs는 platform을 구조물로 분리하지만 street_compile.py prepare_obstacles에서는 canopy/shelter만 제외한다. platform 외곽 전체가 보행 장애물에 들어가 경로 면에서 잘린다. FACILITY_HEIGHTS.platform=3이라는 기본값도 승강장 바닥과 지붕 높이를 구분하지 못한다.

예: 로마 way/1356147714 ↔ 승강장 way/1002063950, 아테네 way/204851496 ↔ relation/19806043 및 platform_edge way/204851523. 후자는 열린 승강장 경계선을 면으로 닫아 해석하는 문제도 추가 점검해야 한다.

대응: 통행 가능한 승강장 데크, 기둥/벽 장애물, 지붕을 분리하고 데크를 같은 층의 보행면 검증에 포함한다. platform을 무조건 삭제하거나 검사에서 통째로 빼는 방식은 피한다.

### 2. 계단·관람석·상층 경로의 층위를 지상으로 평탄화
로마 실패 경로 중 74개가 steps이고, 43개 경로는 building=grandstand와 겹친다(두 집계는 중복). 관람석 외곽이 일반 건물 점유면으로 들어가 위의 계단을 삭제한다. 로마 14개 경로에는 level=1, 2, -1;0, 0;1, 1;2가 명시되어 있으나 eligible 및 보행면 생성 조건은 layer/bridge/tunnel/indoor 중심이며 level을 활용하지 않는다.

예: 로마 way/598205238은 level=1인데 높이 3.3m의 Colombario B(way/633905155)와 지상에서 충돌한다. 아테네 way/116783103·way/116800278과 겹치는 건물 way/116783102도 level=1이나 buildingVerticalFields는 이 level을 수직 점유로 해석하지 않는다. 실제 하부 통과 가능성은 추가 근거 없이 단정하지 않는다.

대응: 공통 경로 층위(지상/상층/지하/층간 연결)를 먼저 만들고 계단을 층간 연결로 처리한다. 미지원 상층은 명시적으로 따로 검증·표시하고 지상 단절과 섞지 않는다.

### 3. 수역 보정은 차량 중심이며 보행 횡단을 놓침
prepare_obstacles의 수역 횡단/제방 처리 대상은 data.roads뿐이다. data.walking은 같은 절차에 참여하지 않아 수로와 겹친 길이 잘린다. 보행 source에는 ford 같은 횡단 근거도 보존되지 않는다.

아테네 기존 미분류 5곳은 모두 w=24인 선형 수로 안에 있었다. 관련 수역 객체에는 osmId/waterInfo도 없어서 24m가 실측인지 추정인지 역추적할 수 없다. refreshStreetObjects가 도로/건물은 원본으로 재생성해도 water는 기존 청크에서 유지한다. 새로운 보행선과 옛 수역 형상이 섞인 입력이다. 이 자료만으로 실제 하천 폭이 잘못됐다고 확정할 수는 없다.

대응: 수역도 같은 원본으로 갱신해 ID·폭 근거·계절성·복개·횡단 정보를 보존한다. 그 다음 짧은 횡단은 근거에 따라 보행교/암거/여울로, 하천을 따라가는 길은 제방 동선으로 구분한다. 모든 수역 충돌에 다리를 만들거나 수역을 삭제해서는 안 된다.

### 4. 랜드마크와 낮은 건물의 통과 모델 부재
로마 콜로세움의 covered=yes 경로 등 4개는 보호된 landmarkModel 외곽과 충돌한다. normalize_passages가 보호 모델을 제외하므로 실제 아치/회랑과 다른 막힌 평면이 남는다. 별도의 모델 바닥/통로 점유 정보가 필요하다.

일반 건물에는 높이 4m 이상·내부 관통 길이 등의 추정 통로 기준이 있다. 아테네 높이 2.9m 상점 way/175017009과 겹치는 3개 경로는 이 조건에서 빠진다. 이 조건을 낮추기만 하면 없는 통로를 만들 수 있다. 출입구 끝점, 실내 동선, 건물 측면 보도를 먼저 나누어야 한다. 보도는 최대 3m 우회 범위를 넘으면 실제 면 누락이 남을 수 있다.

## 권장 적용 순서
1. 경로와 구조물의 층위/통행면 계약을 공통화하고 승강장·관람석·계단·상층 경로를 분리한다.
2. 수역 원본을 갱신하고 차량과 보행이 함께 사용하는 횡단·제방 설계를 적용한다.
3. 랜드마크 통행면과 출입구/실내 경로 정책을 추가한다.
4. 같은 층의 면 연속성과 층간 연결을 따로 검사하고 전체 도시 재빌드를 실행한다.

진단 오차 6cm를 늘리거나 문제 경로를 일괄 제외하는 수정은 원인을 해결하지 않는다. 이번 작업은 원인 분석 및 수역 후보 진단 수정이며 전체 재빌드/릴리스 교체는 실행하지 않았다.
