# 부산 랜드마크 지도·사진 기반 외형 개선

## 정확도와 범위
뷰어에 등록된 19곳 주변 약 500m를 대상으로 지도상의 건물 평면·높이 태그·해안·녹지·길을 연결했다. **전수 실측 복원이나 실사와 동일한 결과는 아니다.** 현장 측량/사진측량 모델은 확보하지 않았으며, OSM 지도 및 공개 치수와 사진 비율을 사용했다. 기존의 밝은 애니메이션 재질은 유지한다.

- OpenStreetMap contributors / ODbL. 원본 19개 API URL과 SHA-256은 `src/world/cities/busan-detail-index.json`에 기록.
- 평면 연결은 경계상자 오차 및 양방향 외곽선 거리 2m 이하의 단일 대응만 사용한다. 불일치 전각 3개는 주변 건물에 억지로 붙이지 않고 보존했다.
- OSM height, 층수×3.3m 추정, 사진/건축 유형 추정은 각각 `osm-height`, `levels-estimate`, `type-estimate`로 구분한다. 미상 높이는 원본을 유지한다.
- 72개 청크별 패치로 나누어 게임/뷰어 공통 로더에서 해당 구역만 읽는다. 서울의 상세 렌더러를 공유하며 원본 지도 JSON은 변경하지 않는다.

## 해안과 교량 처리
OSM의 육지가 왼쪽에 오는 해안선 방향을 이용해 바다 면을 생성했다. 원본 해안선에서만 경계를 만들며, 기준 수면은 0m로 놓는다. 바다 내부 지형 격자만 -0.5m로 내려 녹색 육지가 수면을 뚫는 문제를 줄였다. 이는 수심/조위 실측값이 아니다. 범위 끝과 32m 격자 해안에서 더 정밀한 절벽 모델은 필요하다.

새 교량과 겹치는 지면 도로는 원본 교량 평면 내부 구간만 잘라 중복을 제거한다. 교량은 현재 시각 모델이며 새 상판의 보행 충돌, 교각의 정밀 충돌 및 다층 교량 전투 처리는 별도다. 일반 건물과 담장은 기존 공통 충돌 경로를 사용한다.

## 재생성
1. `python3 scripts/fetch-busan-reference.py`
2. `python3 scripts/build-busan-details.py`
3. Shapely 2.x가 설치된 Python으로 `scripts/build-busan-coast.py` 실행.
4. `npm test -- tests/busanDetails.test.ts tests/seoulDetails.test.ts tests/cityTileLookup.test.ts tests/chunkMesh.test.ts --maxWorkers=2`

현재 목록에서 좌표가 미확정인 동래읍성지·UN기념공원 2곳은 뷰어 등록 19곳에 포함되지 않는다. 좌표를 임의 생성하지 않았으며 대상 목록의 unresolved에 남겼다.

## 교량 접속부 보정 (2026-09-19)
원인: 중앙 교량 면만 별도 높이로 생성하고, 기존 지면 도로를 교량 평면 안에서 제거했다. 중앙 상판 끝부터 지상까지의 접근교가 없어서 단절되었다.

- 광안대교 상·하층 양쪽 4경로, 영도대교 양쪽 2경로를 연결했다.
- 광안대교는 확장 OSM 추출 4개를 추가해 실제 연결된 교량 도로 노드에서 지상 도로까지 추적한다. 남쪽 약 1.42km, 북쪽 약 2.31km. 영도는 양쪽 약 180m.
- 최종 접속점은 게임의 실제 도로 중심선에 맞춘다. 마지막 60m는 게임 도로와 동일한 삼각형 지형 보간으로 양쪽 가장자리 높이를 맞춘다. 상판 높이/종단 곡선은 실측이 아닌 렌더링 추정이며 현재 최대 경사는 4.9% 이하다.
- 연결 구간은 약 12m 단위의 동일한 단면을 공유한다. 각 구간은 해당 지도 타일에 귀속돼 중앙 교량 타일과 독립적으로 스트리밍된다. 교각과 양쪽 난간을 포함한다.
- 원본 지도에 지면 도로로 구워진 고가 차로는 출처 교량 선형에 가깝고 평행한 부분만 제거한다. 횡단 도로는 보존한다.
- 게임/도시 뷰어의 공통 상세 지형 경로를 사용한다. 높이 있는 도로 위 보행 충돌은 별도 작업이며 이번 시각적 연결 보정에 포함되지 않는다.

재생성 순서: `fetch-busan-reference.py` → `build-busan-details.py` → `build-busan-coast.py` → `build-busan-bridge-approaches.py`. 마지막 두 도구는 Shapely 2가 필요하다. 원본 지도는 유지한다. 연결 경로별 출처 way, 단면, 경사 결과는 `public/maps/details/busan/bridge-approach-audit.json`, 추출 URL/해시는 부산 상세 인덱스에 기록한다.


## 도로 표면 통일
교량 구조물과 도로 표면을 분리하고, 상판/진입로의 아스팔트와 차선은 `StreetGeometry`의 지상 도로 재질 및 도색 규칙으로 생성한다. 도시별 asphalt/center/marking 색상, 거칠기, 노면 입자/보수 흔적, 조명 및 원거리 차선 표시 기준을 함께 사용한다. 중앙선은 폭 16m 이상에서 0.18m 이중선, 점선은 폭 22m 이상에서 4m 도색/11m 주기이며 지상과 같은 규칙이다. 진입로 구간 사이의 점선은 누적 거리를 사용한다. 동기 뷰어 및 게임의 워커 준비 경로에 동일하게 적용하며 기존 도로 레이어에 합쳐 추가 재질/드로콜을 만들지 않는다.
