# 도시별 하천 맵 빌드 규칙

청계천의 도심 정비 단면은 특정 시범구역의 설계다. 모든 하천을 청계천처럼 직선·일정 폭·양쪽 도로/콘크리트 제방으로 바꾸지 않는다. 자연스러운 이동과 연결을 우선하되, 원본 지도에 있는 굽이·폭 변화·섬은 보존한다.

## 분류와 적용 범위

`waterInfo`를 OSM 추출 → 중간 지도 → 청크 → 2×2 압축까지 보존한다. 정본은 `scripts/water-build.mjs`, 런타임 타입은 `src/world/MapData.ts`다. 도시 이름이나 주변 건물 밀도로 하천 종류를 추정하지 않는다.

| style | 판단 근거 | 빌드 처리 |
| --- | --- | --- |
| natural | 정비/운하 근거가 없으면 보존형 기본값 | 원본 외곽·굽이·섬 유지. 제방/도로 자동 부착 없음 |
| engineered | 명시적인 channelized=yes 또는 waterway:channelized=yes | 원본 형태 유지. 별도 검토한 지역 레시피가 있는 범위에서만 단면 재설계 |
| canal | water=canal 또는 waterway=canal | 원본 수로 형태 유지. 임의 직선화/폭 통일 없음 |

`kind`는 river/stream/canal/lake/pond/reservoir/unknown이다. natural 기본값은 **자연하천임을 실증했다는 뜻이 아니라, 임의로 정비하지 않는 보존 정책**이다. 구형 캐시는 종류를 복구할 수 없어 unknown + styleSource=legacy로 표시한다.

청계천은 `buildCitySurfaces('seoul')`에서 기존의 지역 레시피를 재생성한다. 런타임 적용은 서울 셀과 시범구역 범위로 제한되어 있다. 이 레시피의 일정 폭 수면, 보행로, 옹벽, 난간, 도로 이동을 다른 하천으로 확장하지 않는다. 새로운 정비 하천은 원본 범위와 설계를 별도로 검토한 뒤 지역 레시피를 등록한다.

## 공통 처리

- 수역 폴리곤이 있으면 외곽과 holes를 유지한다. 폭 변화와 섬을 일정 폭 중심선으로 대체하거나 볼록껍질로 덮지 않는다.
- 선형 하천은 width 태그를 우선한다. m/ft를 처리하고 모호한 범위/잘못된 값은 배제한다. 폭이 없으면 기존 river 24m, stream/canal 6m를 추정값으로 명시한다. 선만 있는 데이터로 실제 폭 변화를 복원할 수는 없다.
- 물가와 작은 섬의 청크 분할은 cm 정밀도를 사용한다. 일반 도로/건물의 기존 정밀도는 유지한다.
- 선형 하천은 반폭만큼 청크 경계 바깥의 중심선도 보존한다. 중심선이 옆 타일에 있다는 이유로 현재 타일의 물가가 잘려 나가는 현상을 막는다. 최종 표면 텍스처는 타일 범위로 잘린다.
- 명시적인 복개/지하 구간만 지표에서 제외한다. 복개 하나 때문에 연결된 지표 하천 전체를 숨기지 않는다. tunnel=no는 지하가 아니다. 태그 누락은 원본 수정 대상이며 연결성만으로 추정하지 않는다.
- 도로 병합 시 bridge/tunnel/layer가 다른 구간은 합치지 않는다. 구조 정보가 청크까지 남아 도로 높이 보정이 교량을 지상도로로 취급하지 않게 한다.

## 검증과 실행

```sh
npm run build:map -- <map-id>
npm run audit:water -- gyeongbokgung busan
npm run audit:city-surfaces -- seoul busan rome athens
```

`build-maps`와 `refetch-water`는 같은 추출 규칙을 사용한다. `build-world`는 기존 청크를 삭제하기 **전에** 수역 형상/폭/분류를 검사한다. 잘못된 입력은 빌드를 중단한다. `build/<map-id>.water-audit.json`에는 분류 수, 구형 데이터/추정 폭 수, 섬 수와 도로 겹침 후보를 기록한다.

도로 겹침은 4m 간격의 중심선 표본 검사다. 교량·터널·다른 layer는 제외하고, 섬 내부도 물로 취급하지 않는다. 모든 근접 충돌이나 도로 전체 폭을 검사한 것은 아니며, 물을 가로지른다고 임의로 다리를 만들거나 물길을 옮기지 않는다. 특히 구조 태그가 소실된 구형 캐시의 결과는 검토 후보이지 확정 오류가 아니다. 최대 100곳의 맵 로컬 좌표와 원본 ID(없으면 배열 인덱스)를 남긴다.

모든 도시의 맵 빌드/압축 전 표면 검증에 `tests/waterBuild.test.ts`가 포함된다. 굽이/섬/폭 변화의 타일 분할 전후 일치, 중심선 없는 타일의 물가, 교량 구분, 복개 구간, 겹침 판정을 검사한다. 서울은 기존 청계천 형상/접지/차선 검사도 함께 실행한다.

## 기존 데이터와 남은 범위

이미 배포된 청크/압축/Releases는 자동으로 바뀌지 않는다. 누락된 OSM 태그까지 반영하려면 캐시 원본에서 `build-maps`를 포함한 파이프라인을 다시 돌려야 한다. `build-world`만 실행하면 기존 형태는 보존하지만 사라진 태그는 복구하지 못한다. 이후 기존 압축/게시 절차를 따른다.

이 변경은 분류·원형 보존·청크 이음·검증을 공통화한 것이다. 일반 하천의 수면은 여전히 기존 지형 표면 표현을 사용한다. 모든 하천의 높이를 재설계하거나 자연형 강둑 메시를 새로 생성한 것은 아니다. DEM 요철을 해결하는 수계별 수면/강둑 생성은 이 분류와 원본 형상을 입력으로 후속 구현해야 한다. 청계천 독립 수면/옹벽 구현은 계속 시범구역 전용이다.

## 서울 전체 재빌드에서 보강한 연결 규칙

OSM의 교량 본체와 일반 진입로는 별도 way로 나뉠 수 있다. 청계천 생성기는 교량 태그를 보존하고, 강둑 가까이에서 교량 끝과 연결되며 진행 방향도 이어지는 짧은 진입 구간까지 상판 지지를 연결한다. 하천과 나란한 강변 도로에는 전파하지 않는다. 실제 재빌드 형상의 도로 폭 전체 표본 검사로 하천에 잘리는 구간이 없는지 확인한다. 검증기의 좌표 정밀도도 수역은 cm, 그 밖의 기존 형상은 m 규칙으로 분리한다.
