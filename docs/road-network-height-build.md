# 연결 도로망의 높이 보정

## 목적과 공통 경로

실측 DEM을 그대로 따르는 것보다 자연스러운 주행과 주변 사물의 접지를 우선한다. 위치별 좌표 예외를 추가하지 않고 `build-city-surfaces.mjs`가 모든 등록 도시에서 `build-road-network-grades.mjs`를 실행한다. 서울의 청계천 레시피와 차선 생성 이후, 최종 검증 이전에 실행한다. `build-pipeline.mjs`에서도 동일 경로를 호출한다. 기존 완성 청크만 재처리할 때도 같은 명령을 사용한다.

1. 현재 지형·도로 보정과 도시별 고증 데이터를 적용한 최종 표면을 읽는다. 이전 network 결과는 입력에서 제외한다.
2. 지상도로의 공통 꼭짓점으로 연결망을 만들고 긴 구간은 최대 16m 간격으로 나눈다. 청크 경계에서도 같은 좌표를 공유한다. 좌표가 교차한다는 이유만으로 임의의 입체교차를 연결하지 않는다.
3. 길이에 반비례한 이웃 가중치로 굴곡을 완화한다. 직선의 일정한 오르막은 유지하며, 같은 높이의 교차로는 한 정점을 사용한다. 교량·터널·양수 layer는 일반 도로망에서 제외한다.
4. 도로망 목표 높이를 도시 공통 격자에 맞춘다. 도로와 건물 주변만 처리하며 하천/수면, 고증 지형, 교량 주변, 바다와 데이터 바깥을 보호한다. 보호 영역 주위 한 격자도 고정한다. 한 번의 보정 한도는 ±15m다.
5. 기존에 통과하던 도로에서 새 급경사·굴곡 경고가 생기거나 기존 경고의 경사/굴곡이 0.2%p 넘게 악화되면 해당 표본을 지지하는 격자 정점의 보정을 보류하고 다시 검사한다. 반복 후에도 새 경고가 남으면 저장을 중단한다.
6. 지면과 도로에 동일한 높이 변화량을 저장한다. 건물·담장·가로수 등은 기존 공통 지면 질의를 사용하고 수면의 추정 고도는 마지막 지면을 기준으로 다시 계산한다. 별도의 덮개 폴리곤을 추가하지 않는다.

기존 도로 렌더링 격자(서울은 약 32m)는 유지한다. 연결망의 세밀한 표본을 격자에 맞추므로 이것만으로 좁은 골목의 모든 횡단면이 정밀하게 재현되는 것은 아니다. 보정 한도에 걸린 지형과 보호 구역 주변의 잔여 경고는 숨기지 않는다.

## 저장과 실행

`public/maps/road-grade/<cell>/<chunk>.json`의 `network`에 `[index, expectedLand, expectedStreet, delta]`를 저장한다. 게임·뷰어·Worker가 사용하는 `MapCorrections`의 마지막 높이 단계에서 적용한다. 원본 표면이 바뀌면 전체 패치를 적용하지 않으며, 빌드 검증은 이를 실패로 처리한다. 중복 적용하지 않는다. 실시간 반복 계산은 없다.

```sh
node scripts/build-city-surfaces.mjs seoul
node scripts/build-map-bundles.mjs seoul
```

수정 전 패치 파일은 `build/road-network-backups/<city>/<run>/`에 보관한다. 같은 셀에 여러 도시가 있을 때는 청크 소유자에 해당하는 도시만 생성한다. 결과는 2×2 묶음의 기존 roadGrade 항목에 포함되며 GitHub Releases 갱신은 별도 게시 절차를 따른다.

청계천 생성기가 읽는 기본 도로 패치의 해시는 network/refinement 필드를 제외하고 계산한다. 최종 보정이 자신이 소비하는 선행 레시피를 다시 무효화하는 순환 의존성을 방지한다.

## 검증

- `roadNetworkGrade.test.ts`: 일정 경사 보존, 돌출 감소, 교차로 공통 정점, 입체교차 제외, 보호 지형 유지, 조각 사이 꺾임, 패치 재적용/오래된 입력 거부.
- `validate-road-network-grades.mjs`: 실제 전체 청크에서 입력 높이 일치, 패치 적용 여부, 중복 인덱스·범위·유한값·이동 한도, 새 지면/도로 경계 틈 여부.
- `audit-city-roads.mjs`: 기존 중심/양측 도로 검사와 별도로 연결된 두 선분 사이의 꺾임을 검사한다. 일반 지상도로와 교량·고가 후보를 분리 집계한다. 고증 상판/진입로 데이터가 있으면 그 단면을 검사한다. 상판 자료와 매칭하지 못한 OSM 교량은 지면 검사만으로 정상이라고 인증하지 않는다.
- 기존 청계천·서울역 도로 실제 삼각형, 보행 지지 높이, 담장 접지, 수면 위치, Worker 전달 검사도 계속 실행한다.

```sh
# 같은 검증기로 새 보정 적용 전 기준값 생성
node scripts/audit-city-roads.mjs seoul --without-network
# 기준값 대비 경사·굴곡·연결부 꺾임이 악화되면 실패
node scripts/audit-city-roads.mjs seoul --compare build/seoul-road-profile-network-baseline.json
```

`build/<city>-road-network-build.json`, `build/<city>-road-network-validation.json`, `build/<city>-road-profile.json`에 결과를 남긴다. 내부 결측, 오래된 패치, 새 경계 틈은 필수 실패 조건이다. 남은 경사 후보는 `qualityPassed:false`이며 `--strict`로 전체 품질 통과를 요구할 수 있다. 정상 산길과 입력 자료가 부족한 입체도로가 포함되므로 일괄 평탄화로 경고를 제거하지 않는다.


## 서울 적용 결과 — 2026-09-27

전체 1,600개 청크, 796,582개 도로 선분과 672,060개 직진 연결부를 같은 조건으로 비교했다. 1,378개 청크의 보정값 633,800개를 저장했다(공유 경계 정점 중복 포함).

| 검사 | 적용 전 | 적용 후 |
|---|---:|---:|
| 18% 초과 경사 선분 | 20,325 | 18,714 |
| 급격한 굴곡/반전 선분 | 9,976 | 9,648 |
| 연결부의 급격한 꺾임 | 3,351 | 3,065 |

최종 게임 높이 질의에서도 새 선분 경고 0개, 기존 경고의 0.2%p 초과 악화 0개를 확인했다. 새 청크 경계 틈, 오래된 패치, 내부 결측은 0건이다. 기존에 발견된 도시 외부 표본 1,985개는 별도 집계하며 내부 결측으로 숨기지 않는다. 기존 회귀 검사와 공통 검사를 포함한 84개 테스트, 타입 검사 통과.

잔여 경고는 미해결 상태다. 교량 아래 지형을 검사한 후보 1,616개와 별도 고가 후보 179개는 일반 지상도로와 분리했다. 서울의 매칭 가능한 고증 상판 단면이 이번 검사 입력에는 없어 교량 정상 판정을 내리지 않았다. 현재 최고 경사 121% 후보도 남아 있다. 따라서 전체 도로 품질 통과(`qualityPassed:true`)로 보고하지 않는다.

2×2 묶음 400개를 재생성했고 압축 용량은 약 22.50MB에서 29.33MB로 증가했다(십진 MB). 계산은 빌드에서 완료하고 게임에서는 저장된 높이만 적용한다. Release 게시와 커밋/푸시는 별도다. 상세 비교는 `build/seoul-road-network-final-check.json`에 남긴다.


## 잔여 경고 분류와 국소 8m 세분화

`build-city-surfaces.mjs <city>`가 기존 시설 분류·소형 건물 높이·도시별 선행 레시피·도로 연결망 보정 다음에 `build-local-road-refinements.mjs`를 실행한다. 도시 좌표를 미리 나열하지 않으며 같은 절차를 모든 등록 도시에 사용한다. 현재 지원 격자는 1,024m 청크/33×33 원본이다. 다른 격자는 임의로 변환하지 않고 빌드를 중단한다.

1. 연결망 빌드가 `build/<city>-road-network-scope.json`에 지점별 보호/제한 조건을 기록한다. 저작 지형, 물, 입체도로, 기존 경계 불일치, 주변 건물 없음, 데이터 경계/해수면, 보정 한도, 다른 도로 악화 방지를 위한 복원을 구분한다. 여러 조건이 겹칠 수 있다. 최종 기본 표면 지문이 다르면 세분화 빌드를 거부한다.
2. 전체 도로의 중심과 양측을 검사해 급격한 굴곡 또는 35% 이상 급경사가 있는 지상도로를 찾는다. 보호 구역 및 타일 가장자리 후보를 제외하고 심각도순으로 최대 48개 후보를 검토한다. 실제 경고가 감소하고 다른 도로/연결부가 악화되지 않는 **최대 8개 청크**를 채택한다. 이는 확대 전 성능을 제한하는 공통 예산이다.
3. 선택 청크의 기존 삼각형 표면을 그대로 129×129(8m)로 세분화한 후 후보 반경 224m 안에서 최대 8m의 높이 보정을 계산한다. 반경 외곽과 타일 가장자리는 점진적으로 보정량을 줄이고 가장자리 32m는 원형을 유지한다. 물·고가도로·별도 제작 지형은 이동하지 않는다. 일정한 평면 경사를 억지로 평평하게 만들지 않는다.
4. `roadGrade.refinement`에 소스 지문과 희소 높이 차이만 저장한다. 원본 청크를 16배로 저장하지 않는다. `MapCorrections`에서 기존 지형 격자를 교체하고 지면·도로에 같은 차이를 적용한다. 두 번째 바닥 메시나 별도 이동 표면을 덧붙이지 않는다. 게임·뷰어·Worker 모두 동일한 보정 함수를 소비한다.
5. 입력 불일치, 중복/범위 오류, 과도한 높이 변화, 타일 가장자리 변화, 새 경고, 기존 경고 악화, 연결부 악화를 검사한다. 최종 검증에서 실패하면 2×2 묶음 생성도 중단한다. 빌드 결과 파일은 `build/<city>-road-refinement-build.json`, 검증 결과는 `build/<city>-road-refinement-validation.json`이다.

보호 조건은 도로 표본을 지지하는 격자 모서리들의 합집합으로 기록한다. 이것만으로 실제 도로가 산길인지, 교량 상판이 정상인지 확정하지 않는다. 채택되지 않은 후보(`no-safe-improvement`)와 예산 때문에 미검토된 후보도 남긴다. 경고 자체와 품질 기준을 숨기거나 완화하지 않는다.

```sh
# 공통 생성 순서 전체
node scripts/build-city-surfaces.mjs seoul
# 세분화 전 기준과 최종 결과를 동일 검증기로 비교
node scripts/audit-city-roads.mjs seoul --without-refinement
node scripts/audit-city-roads.mjs seoul --compare build/seoul-road-profile-refinement-baseline.json
# 검사 통과 후 일반 지도/랜드마크/모든 높이 패치를 함께 묶음
node scripts/build-map-bundles.mjs seoul
```

`roadRefinement.test.ts`는 원본 삼각형 보간 보존, 지면/도로 상대 높이, 오래된 입력 거부, 가장자리 고정, 실제 지형 메시와 보행 높이, Worker 전달 후 동일성을 검증한다. 세분화에 따른 청크당 지형 삼각형 수는 2,048→32,768개이므로 도시 전체를 일괄 8m 격자로 바꾸지 않는다. 도로 세분화 비용도 늘 수 있어 확대 전 별도 성능 측정이 필요하다.


### 향후 보정 추가 규칙

- 계산은 `build-city-surfaces.mjs`의 공통 순서에 등록하고, 결과 적용은 `MapCorrections` 한 곳에 둔다. 도시 뷰어나 게임에만 임시 바닥·예외 좌표·별도 높이 공식을 추가하지 않는다. 의도적으로 제작한 하천/랜드마크만 도시별 레시피로 유지한다.
- 선행 표면이 바뀌면 후속 `network`/`refinement`를 다시 생성한다. 후속 보정 데이터는 선행 레시피의 입력 해시에서 제외해 순환 무효화를 방지한다. 보정 생성기의 변경 이력은 선행 레시피 검증에 반영한다.
- 실제 렌더 삼각형/보행/Worker 높이 일치, 타일 경계, 인접 도로 악화 검사를 `validate-city-surfaces.mjs`에 등록한다. 압축 및 게시 단계는 동일 검증을 통과해야 한다. 경고 한도를 완화하거나 보호 지형을 일괄 평탄화해서 숫자만 줄이지 않는다.


### 서울 국소 세분화 검증 결과 — 2026-09-27

공통 생성 순서 전체를 실행하고 1,600개 청크를 검증했다. 보호 조건을 통과한 후보 31개 중 심각도순 13개를 시도해 8개 청크에 12,904개 희소 높이 보정값을 저장했다. 5개는 안전한 개선이 없어 제외했으며 18개 후보는 적용 예산 때문에 미검토 상태다.

| 검사 | 32m 연결망 보정 후 | 국소 8m 보정 후 |
|---|---:|---:|
| 급경사 선분 | 18,714 | 18,701 |
| 급굴곡/반전 선분 | 9,648 | 9,644 |
| 연결부 꺾임 | 3,065 | 3,064 |

전체 선분 비교에서 새 경고 및 기존 경고의 기준 초과 악화 0건, 새 경계 틈/오래된 패치/내부 결측 0건이다. 공통·회귀 테스트 88개와 타입 검사를 통과했다. 최고 경사 121% 후보와 다수 잔여 경고는 여전히 남아 있으며, 전체 도시 품질 통과로 간주하지 않는다.

400개 2×2 묶음의 해시 및 8개 보정의 실제 포함을 확인했다. gzip 총량 29,326,747→29,395,280바이트로 **68,533바이트(약 0.23%)** 증가했다. 원본의 33×33 격자를 모두 고밀도로 저장하지 않고 희소 차이만 묶음에 포함한 결과다. 상세 결과는 `build/seoul-road-refinement-final-check.json`, 실행 기록은 `build/seoul-local-road-final.log`에 있다. Release 게시/커밋은 이 작업에 포함하지 않았다.


도로 폭·인도·식재 배치의 단일 기준과 적용된 top-down 단면 설계는 [공통 가로공간 계약](street-layout-contract.md)을 따른다. 높이 보정 전에 최종 수평 배치를 확정하며, 오래된 레시피 폭을 렌더 단계에서 다시 적용하지 않는다.
