# 공통 가로 구역 빌더

## 적용 범위와 원칙

2026-09-27 종로–청계천 연속 구역에 적용했다. 등록은 config/street-regions.json에서 한다. 서울 등록 구역은 로컬 좌표 [86580,47740,88050,48390], 약 1.47 × 0.65 km이며, 주변 160 m 입력을 함께 읽는다. 결과는 84_46, 85_46, 84_47, 85_47 네 청크와 42_23 압축 묶음으로 전달된다. 서울 전체나 다른 도시가 새 빌더로 전환된 것은 아니다.

목표는 원본 수치를 그대로 복제하는 것이 아니라 이동할 때 연결되고 자연스러운 거리다. 제보 좌표는 검증 지점으로 사용하며 생성 코드의 예외 분기로 사용하지 않는다. 구역 밖은 기존 빌더를 유지한다. 게임과 도시 뷰어는 같은 산출물, 지지면 및 충돌 경로를 사용한다.

## 처리 순서

1. 원본 PBF에서 구역과 완충 영역을 추출한다. 원본 ID, 노드, 도로 종류·이름·방향·차선 수·폭 출처·높이 층을 보존한다. 기존 청크에서 의미를 잃은 선을 모두 차도로 가정하지 않는다.
2. 통행 연결을 먼저 예약한다. 일반 건물의 근사 외곽은 제한적으로 조정할 수 있지만 랜드마크는 보호하고, 건물 삭제·분할 또는 면적 25% 초과 변경은 허용하지 않는다. 공동 노드를 함께 조정하고 도로 축 이동은 원래 선에서 12 m 이내로 제한한다.
3. 이름·종류·높이 층이 같은 차도들을 가로 묶음으로 처리한다. 가까운 왕복 차도의 불필요한 틈을 합치되 실제 교통섬, 수역, 보호 구조물은 제외한다. 다른 이름의 평행 도로를 무조건 합치지 않는다.
4. 차도 전체와 사용 가능한 공간에서 보도를 함께 배분한다. 교차로는 합쳐진 면이며 원본 선마다 보도 테두리를 만들지 않는다. 좁은 연결로는 보도 때문에 끊어지지 않도록 공유 공간을 허용한다.
5. 차도·보도·연석·중앙선을 최종 면으로 확정한다. 원본 방향별 선 대신 최종 차도 단면의 중앙에서 노란 중앙선을 만든다. 일반 흰 차선은 생성하지 않는다.
6. 최종 면을 구멍과 경계가 보존되는 제한 델로네 삼각분할로 변환하고 공통 보정 지형의 삼각면 높이를 적용한다. 가로수/가로등은 최종 보도에서 정하며, 실제 받침 사각형 전체의 여유를 검사한다. 담장은 확정 차도를 침범하지 않도록 잘라낸다.
7. 설계가 끝난 면을 청크로 나누고 정점·인덱스로 저장한다. 이동 지지 높이는 렌더링에 쓰는 바로 그 삼각형을 조회한다. 조정한 건물 외곽을 표시와 충돌에 같이 사용한다.
8. 경로·면적·실제 메시 검증을 통과한 후 지도 보정 파일과 2×2 묶음에 반영한다. 압축 파일을 먼저 기록하고 인덱스를 마지막에 교체한다.

## 기존 높이 보정과의 관계

이번 단계는 가로의 수평 면 배분 및 그 최종 면을 공유하는 구조의 전환이다. 높이는 기존 공통 도로 높이/지형 보정과 청계천 하천 설계를 입력으로 사용한다. 도시 전체의 새 수직 설계기나 다층 교차로 해석기를 완성한 것은 아니다. 복잡한 입체 교차로, 다른 도시의 하천, 시범구역 외곽의 신구 접속부는 확대 전 추가 검증 대상이다. sourceNodes 등 의미 정보는 보존하지만 도시 전체의 신호/차량 경로 그래프를 제공하지는 않는다.

## 실행

Node 의존성과 Python 3.10 이상, Shapely가 필요하다. 설치 버전은 scripts/requirements-map-build.txt를 따른다. OSM 원본은 로컬 캐시를 사용하며 자동 네트워크 다운로드는 하지 않는다.

~~~bash
python3 -m pip install -r scripts/requirements-map-build.txt
# 등록된 구역을 모두 준비 → 설계 → 삼각형 생성 → 검사 → 보정 파일 반영
npm run build:street-regions -- seoul jongno-cheonggye
# 시범구역이 속한 기존 2×2 묶음만 재생성하여 게임/뷰어에 활성화
node scripts/pack-street-region.mjs seoul jongno-cheonggye
# 도시 전체 기존 높이 보정까지 재생성할 때도 위 구역 빌드가 포함된다
npm run build:city-surfaces -- seoul
~~~

config/street-regions.json의 source 또는 MAP_OSM_PBF로 원본 경로를 설정한다. OSMCONVERT로 추출 도구, MAP_PYTHON으로 Python 실행 파일을 지정할 수 있다. 원본 경로·크기·수정시각·구역이 바뀌면 추출 캐시를 다시 만든다. 명시적인 재추출은 prepare-street-region.mjs의 --refresh-source를 사용한다.

build/streets 아래 input, regions, routes, plans, audit, surface-audit, mesh-audit 파일은 진단/재현용 중간 산출물이다. 실행 시에는 public/maps/road-grade의 streetPlan과 이를 포함하는 압축 묶음만 사용한다. 기존 build-map-bundles 및 Releases 원본 백업도 전체 보정 객체를 포함하므로 별도의 새 저장소가 필요하지 않다. 위 명령은 Git 커밋·푸시 또는 Releases 게시를 하지 않는다.

## 검증과 실패 처리

- 최종 면 위 경로 샘플뿐 아니라 선 전체의 누락 길이를 검사한다.
- 차도/건물, 차도/보도 겹침을 검사한다.
- 렌더링용 삼각형 전체를 다시 합쳐 설계 면과 비교한다. 수 mm 양자화 여유 밖의 누락/추가 면적을 차단한다. 중앙 경로만 검사하면 건물 모서리를 침범하는 삼각형을 놓칠 수 있다.
- 가로수 받침은 원 대신 실제 사각형으로 검사하며 청크 경계에서는 양쪽 보도를 함께 검사한다.
- 게임과 같은 지지면 및 건물 충돌로 통행 경로를 검사한다. 내부 청크 이음의 높이/누락도 검사한다.
- 감사 결과는 plans 파일의 SHA-256을 보관한다. 재생성 이후의 낡은 검사 결과로 게시할 수 없다.
- 검사 실패 시 새 보정 파일을 반영하지 않는다. 파일 교체 전 원래 보정 파일을 build/streets/backup-*에 최초 한 번 보관한다. 여러 보정 파일의 교체 자체는 파일별이며, 런타임 활성화 기준은 마지막에 교체하는 압축 인덱스다.

회귀 검사는 tests/street_compile_test.py, compiledStreet.test.ts, CollisionWorld.test.ts, seoulStreetLayout.test.ts 및 기존 도로 메시/높이 검사를 사용한다. 합성 사례는 평행 왕복도로, 실제 교통섬, 서로 다른 평행도로, 교차로, 장애물 우회, 교량/물/벽, 입력 순서를 포함한다.

통행 중심선이 연결된다는 결과만으로 모든 폭의 드론이 모든 골목을 통과한다고 단정하지 않는다. 다음 확대 시 도로 등급별 최소 유효 폭, 연속 보행망, 신구 구역 외곽 접속과 다양한 높이 층을 추가 확인해야 한다. 서로 겹치는 빌드 구역의 공동 해결은 아직 지원하지 않으므로 등록 구역을 중첩시키지 않는다.
